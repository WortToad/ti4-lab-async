# Automated testing

Use Node 26.8.2 (`nvm use`) and `yarn install --frozen-lockfile`. SQLite tests use the native `better-sqlite3` module; dependencies installed under another Node major must be rebuilt or reinstalled.

```sh
yarn test:run                         # All unit and integration tests
yarn test app/routes/baseDraftFlows.test.ts --run  # One flow suite
yarn playwright install --with-deps chromium firefox webkit  # Once per machine
yarn test:e2e                        # Chromium, Firefox, and mobile WebKit
yarn test:visual                     # Current desktop/mobile appearance baselines
yarn test:e2e --project=desktop      # Desktop only
yarn test:e2e --project=firefox      # Core Firefox journeys
yarn test:e2e --project=webkit-mobile # Core mobile WebKit journeys
yarn build && yarn typecheck && yarn lint
```

`yarn test` retains Vitest's watch mode. The separate Vitest configuration limits concurrency to four workers and only discovers application tests; generated React Router types are not test suites. Route discovery excludes test files so they cannot become public endpoints. CI runs the production build, type checking, lint, all unit/integration tests, and browser tests, with focused tests prohibited.

Browser tests build the production application with the `/ti4` base path, then start an isolated server on port 3187. Set `TI4_E2E_PORT` to choose another port. Each run creates a unique directory under `.cache/browser-tests-*` for both its SQLite database and compiled application, disables Discord/R2/analytics, and removes the directory when the server exits. The test runner does not reuse a running application or modify its `build/` directory or database. `TI4_BUILD_DIRECTORY` selects the same output directory in React Router and the server, so test builds cannot replace the assets being served by a running preview.

The browser connection uses HTTPS with a temporary self-signed certificate
generated by `openssl`. A local TLS proxy forwards requests and WebSocket
upgrades to the production HTTP server on an ephemeral port, matching the
deployment's TLS termination. Playwright trusts the temporary certificate;
production `Secure` cookies remain enabled in every engine. This matters because
WebKit does not accept those cookies over loopback HTTP.

Failed browser tests retain screenshots and Playwright traces in `test-results/`; CI uploads them as an artifact. Open a trace with `yarn playwright show-trace test-results/<test>/trace.zip`. Tests use locator assertions and controlled promises rather than fixed sleeps or retries.

Most complete games run through the real engine or server route with actual persistence; browser tests exercise setup, map previews, editor journeys, complete standard drafting/replay, and complete RAW/Mantis map building. Desktop and mobile Chromium run the entire browser suite. Firefox and mobile WebKit run `flows.spec.ts`, `map-building.spec.ts`, `map-recovery.spec.ts`, and `standard-completion.spec.ts`, including all five lobby families' admin controls. External Discord delivery, R2 uploads, operating-system notification delivery, and physical-device behavior are outside these suites. This is a flow inventory, not a claim of exhaustive branch or visual coverage.

`responsive-map.spec.ts` checks that every tile in 2–5-ring galaxies stays inside the map at 320px, 390px, tablet, landscape and desktop sizes. It also exercises mobile zoom, touch panning, tap-to-edit, collapsed tools and undo. `search-indexing.spec.ts` verifies search-exclusion headers on pages, static images, APIs, redirects and errors, server-rendered robots metadata, client navigation and robots.txt at the domain root and `/ti4`.

When adding a flow, cover a successful journey and its meaningful rejection/recovery paths, keep random generation seeded, and update this inventory. Keep private state fixtures synthetic and avoid live integrations.

The map suites guard against previously uncovered failures: Mantis losing its clickable placement targets when drag-and-drop is disabled, Standard 4p offering incompatible slice extraction, Standard 5p failing to prepare a preset faction draft, and Texas accepting layouts with incompatible tile counts. Standard 4p/5p can draft factions on their complete maps; slice drafting requires a compatible layout. External map strings preserve system positions and rotations, but encode home placeholders without seat identity and use the same empty marker for open and closed spaces; the native share format preserves that editor information.

`appearance.spec.ts` compares eleven pages on desktop and mobile against reviewed screenshots of the current interface, using Playwright 1.63.0 on Linux. A fixed preview fixture removes random draft generation from the comparison. Up to five isolated antialiasing pixels are allowed; layout and text changes still fail. Keep browser and OS versions consistent, inspect differences, and only replace baselines for intended design changes. These checks also reject browser console errors. See [upgrade notes](dependency-upgrade.md) for package compatibility limits.

`bag-submission.spec.ts` creates a lobby for every bag variant, joins three players, starts the draft, restores pending selections after reload, confirms and undoes picks, and submits a full round. It checks successful POST responses and the resulting next-round state in desktop and mobile Chromium.

`proxy-actions.spec.ts` simulates HTTPS requests forwarded by the hosting edge to
the HTTP server. It verifies six-player Twilight's Fall lobby creation, admin
access after the redirect, client submission validation, and rejection of
submissions from a different host or protocol.

The shared-lobby journeys in `flows.spec.ts` also use `admin-controls.ts` to
exercise every lobby administration operation through the browser for base,
Texas, bag, RAW and Mantis drafts. They make a real pick, save and export a
checkpoint, export current state, undo, restore, reload, and import a downloaded
save. They check recovery snapshots, paused restoration, damaged-save rejection,
confirmation cancellation, renaming, recovery-code rotation, revoked-code
rejection, replacement players, and the bag draft's round rewind. Importing an
older save must keep a released seat empty and resuming disabled until its
replacement joins. All player and recovery contexts use the project's desktop
or mobile device settings.
RAW database regressions also verify that undo preserves renamed and replacement
players' current names and credentials while reverting their draft picks.

`standard-completion.spec.ts` plays all nine standard picks using Enter and Space,
including map-seat confirmation, checks matching final map strings on every
player's device, and steps through the complete replay. This catches controls
that react only to mouse events and failures that setup-only tests cannot see.
It also holds lobby JavaScript downloads to verify that inputs wait for their
handlers and preserve a player's name once loading completes.
The setup journey in `flows.spec.ts` separately holds scripts before enabling
preview creation. Complete-game tests settle background reads before intentional
reloads so navigation cancellation does not masquerade as an application error.

`map-recovery.spec.ts` checks offline, HTTP-error, and malformed-response recovery
for map likes; a pending request blocks duplicate clicks, and a confirmed like
survives reload. Route/database regressions cover simultaneous map publication,
Unicode-only titles, malformed JSON and field types, invalid/incomplete map
strings, unsupported layouts, and missing replay UUIDs. Malformed draft-creation
requests must return 400 without writing a lobby.

See [the testing audit](testing-audit.md) for the reproduced defects and remaining
verification gaps.
